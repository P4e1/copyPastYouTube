# Безопасность

Проверки доступа выполняет сервер. Скрытие кнопки в интерфейсе не заменяет проверку роли и видимости.

## Пароли и сессия

- Пароль хранится только как хеш Argon2 через pwdlib. В логах и в ответах API пароля нет.
- Пароль короче 8 или длиннее 200 символов регистрация не принимает: ответ 422, сам пароль в теле ответа не возвращается.
- Неизвестный email и неверный пароль отвечают одним текстом «Неверный email или пароль». Перед отказом сервер всё равно проверяет хеш, чтобы по времени ответа не отличить чужой адрес.
- `POST /auth/login` и `POST /auth/register` с одного адреса ограничены `AUTH_RATE_LIMIT` попытками в минуту (по умолчанию 20). Дальше ответ 429 и `Retry-After: 60`.
- `POST /auth/login` после проверки хеша выдаёт JWT access. Секрет подписи и срок жизни берутся из окружения (`JWT_SECRET`, `ACCESS_TOKEN_EXPIRE_MINUTES`). Секрет короче 16 символов и шаблоны `change-me` / `change-me-jwt` не дают процессу стартовать.
- Защищённые маршруты без токена отвечают 401. Токен с неверной подписью или истёкший срок — тоже 401.
- Регистрация создаёт только роль `user`. Назначить `moderator` или `admin` может администратор через `POST` или `PATCH /admin/users/{id}/role`. Модератор этот маршрут не вызывает.

## Роли

- `user` управляет своим каналом, своими видео, своими плейлистами, своими комментариями, подписками и жалобами.
- `moderator` видит очередь жалоб и может скрыть или вернуть видео. Чужой канал он не редактирует и роли не раздаёт.
- `admin` делает всё, что модератор, и меняет роли.
- Маршруты `/moderation/*` для `user` отвечают 403. Прямой адрес страницы модерации на фронте тоже упирается в этот отказ.

## Видео и ссылки на файл

- Ключ объекта генерирует сервер. Клиент не присылает путь в бакете.
- Presigned PUT и GET живут короткое время. PUT выдаётся только владельцу на видео в статусе загрузки. GET выдаётся только после правила видимости из [database.md](database.md).
- Private без строки в `video_grants` не получает ни метаданные, ни ссылку. Ответ такой же, как для неизвестного id, чтобы по коду нельзя было перебрать закрытые ролики.
- Скрытое видео не получает ссылку зритель. Владелец видит метаданные с пометкой и без публичной раздачи, пока модератор не вернёт ролик.
- Загрузка ограничена `MAX_UPLOAD_BYTES` и списком content-type видео (mp4). Ссылка на отправку файла живёт 12 часов, а nginx на пути `/videos/` ждёт тело запроса до часа, чтобы большой mp4 не обрывался по короткому таймауту. Чужой `complete` отклоняется.

## Секреты и контейнеры

- Пароли базы, MinIO и секрет JWT задаются переменными окружения. В репозитории только [.env.example](../.env.example) с заглушками `change-me`.
- `.env` в git не коммитится.
- CORS разрешает только адреса фронта из `CORS_ORIGINS`, не произвольный сайт.
- Ответы API несут `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` и `Content-Security-Policy` с `frame-ancestors 'none'`. Nginx страницы ставит те же семейства заголовков и разрешает скрипты и стили только со своего адреса и шрифты Google.
- Образ API и воркера запускается пользователем `appuser`. Первый `.env` пишет [scripts/write_env.sh](../scripts/write_env.sh) со случайными секретами.
